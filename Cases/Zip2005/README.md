# zip-2005

The first target: the SP1 guest of [zip-2005-asm](https://github.com/dhsorens/zip-2005-asm),
re-proved here on the generic layer (`docs/PLAN.md` has the phases; `docs/ELF.md` what the
toolchain can and cannot be trusted for). The end goal is the whole of zip-2005-asm's
result, non-vacuously, with no bridge to its proofs.

## The image

`experiments/zip-2005/out/relocs.elf`: the pinned artifact `zip-2005-asm/artifacts/zip-2005.elf`
rebuilt with `--emit-relocs`, which gives an identical loaded image (entry plus every
`PT_LOAD` segment; `image-digest.sh`) and keeps the relocations that back the
indirect-call target sets. `experiments/zip-2005/RESULTS.md` records the reproducibility
experiments and the exact `build-variant.sh` and `gen-image` commands.

- `Image/`: `gen-image`'s output, one module per function (306, `INDEX.tsv` maps module to
  symbol), the three data chunks, and `Layout`. gen-image cross-checked it, entry by
  entry, against riscv-zkvm's `Interpreter.load`. `Image.lean` imports every function.
- `Loaded.lean`: the layout is well-formed, the entry stack word, and `code_of_run` (any
  state an SP1 run of the image reaches has its code); the decode facts and `CodeOk` of
  the frame-checked functions.
- `Regions.lean`: the address space, named and proved disjoint (stack, `.rodata`,
  `.eh_frame`, `.data`, `.bss`, the TLSF arena, the hint region).
- `Statics.lean`: the protected statics (`.rodata`, `.eh_frame`, the two hooks nothing
  sets), with their load values; `Runtime/STATICS.tsv` is the reviewed list.
- `Owned.lean`: the owning `Env`: the public-values hasher's tag and position, with the
  invariant `syscall_write` and `syscall_halt` keep.
- `HeapEnv.lean`: the `Env` that also owns the allocator (control block and arena), with
  `HeapOk` (`Tlsf.Rep`) in the invariant, and the lifting of the checked table to it.

## `Frame/`: the frame-integrity spike

The first checker (`AsmVerif.RiscV.Frame`) on four functions: `memcpy`, `PadAdapter::next`,
`default_hook` (with its outlined fragment) and `core::fmt::write` (indirect jumps against
a target list). `Fns.lean` defines them, `Gen.lean` emits the annotations (`*Anno.lean`,
untrusted certificates), and each module has the kernel re-check them.

## `Contract/`: the checked table

Generated by `lake exe infer-contracts` (`Tools/Infer.lean`; the command is in
`docs/PLAN.md`'s E2 notes and the memory of the sessions). `Table.lean` holds the `Env`
and the table of 70 interfaces: 68 inferred and certified by the contract checker
(`A_<addr>.lean` the interface and sparse certificate, `V_<addr>.lean` the proof that
`Ctx.sound` gives), and two proved by hand and registered in `Runtime/GIVEN.tsv`
(`memcpy`, `memset`). `All.lean` composes them: every interface of the table holds for
the loaded image (`Contract.all`). `Runtime/CFI.tsv` lists the control-flow premises of
`core::fmt::write`'s argument-formatter sites.

## `Runtime/`: the SP1 runtime, by hand

What the checker cannot derive, proved with the symbolic executor
(`AsmVerif.RiscV.Exec`) against the same interfaces:

- `Entry.lean` (D1): from the loaded state to `main`'s entry; `MainEntry` fixes the
  stack, heap, statics and hasher a run starts with.
- `SysWrite.lean`, `Halt.lean`, `ReadVec.lean` (D2): `syscall_write` keeps the hasher's
  invariant; `syscall_halt` never accepts with a nonzero code; `read_vec_raw` with its
  bump region and `HINT_LEN`/`HINT_READ`.
- `Memcpy.lean`, `Memset.lean` (D3): for every length, with footprints.
- `Tlsf/`, `Alloc/`, `Dealloc/`, `Realloc.lean` (D4): rlsf's heap as memory holds it
  (`Tlsf.Model`, `Heap`, `Class`, `Update`, `Free`, and `Init` as the satisfiability
  witness), and `alloc`, `dealloc` and `__rust_realloc` end to end against it.
- `Panic.lean`, `SysPanic.lean` (D5): panics never accept, along the entry chain down to
  `sys_panic` and `syscall_halt(1)`, given one premise: that `panic_with_hook` never
  accepts (`pwhIface.Holds`). Discharging it is phase E2's zip-2005 instance (the `String`
  path, typed stores).
