# zip-2005

The SP1 guest of [zip-2005-asm](https://github.com/dhsorens/zip-2005-asm), a RISC-V (RV64IM)
program compiled from Rust that checks a Zcash Orchard statement (ZIP 2005). This directory
re-proves zip-2005-asm's result on this repository's framework, without relying on its proofs.

## The result

`Cases.Zip2005.guest_run` (`Top/Guest.lean`): for every guard `G` and step budget `n`, a run
of the loaded image on private input `I` (`start I`, from the ELF's entry point) that accepts
establishes `GuestAccepts I`. That is, `I`'s instance and witness records decode to typed
values satisfying `Zip2005.GuestStatement` (`Bridge/Decode.lean`, `Spec/Zip2005/Divergences.lean`).

It assumes two things:

- `PanicPaths`: thirteen premises, each saying that a panic entry, a reject halt, or the
  formatting path (`format_inner` returns a `String`) never accepts.
- `hIfit`: the input fits the hint area.

Everything else is a theorem about the loaded image: the code of every function stepped, the
entry state, the heap invariant and the allocator contracts. The axioms are `propext`,
`Classical.choice`, `Quot.sound` and `bv_decide`'s certificates; there is no `sorry` and no
`native_decide`.

Trusted besides that: riscv-zkvm's RV64IM semantics, decoder and SP1 step (`stepSp1`), and
that the image here is the binary that runs.

Build: `lake build Cases.Zip2005.Top.Guest`. It imports most of the case, so it is slow; run
`lake exe cache get` first for Mathlib.

## Status

The `PanicPaths` premises are stated directly. They are not yet derived from the proved panic
results (`Runtime/Panic.lean`), and there is no witness that they are satisfiable. Until there
is, the theorem could be vacuous. [`PLAN.md`](PLAN.md) has the phases, the milestone design
and what remains (phases E and F4); [`ISSUES.md`](ISSUES.md) records problems found during
verification. [`docs/ELF.md`](../../docs/ELF.md) says what the toolchain is and is not trusted
for.

Most proofs here use the layer-0 tools (the checker and the symbolic executor) and predate the
lift to Lprog. `black_box`, `memcmp` and `write_vectored` are also proved through the lift
(`Runtime/BlackBox.lean`, `Runtime/MemcmpLprog.lean`, `Runtime/WriteVectored.lean`), and
`memcmp` and `write_vectored` with `lsym` (`Runtime/MemcmpLsym.lean`,
`Runtime/WriteVectoredLsym.lean`). CI builds the two `lsym` modules on every pull request.

## The binary

The pinned artifact `zip-2005-asm/artifacts/zip-2005.elf`, rebuilt with `--emit-relocs`. The
rebuild gives an identical loaded image (entry and every `PT_LOAD` segment) and keeps the
relocations that back the indirect-call target sets. `Image/Layout.lean` records the digest of
the loaded image. The reproduction scripts (the rebuild, the digest and the `gen-image`
command) are not published yet.

**Provenance and licences.** The guest is built from the zip-2005 Rust workspace (from SP1's
project template, MIT). It statically links:

- Rust's `core` and `alloc` (MIT OR Apache-2.0);
- SP1's guest runtime `sp1-zkvm`/`sp1-lib` (MIT OR Apache-2.0, at a fork's revision `f2328b4`);
- the Zcash crates: `orchard`, `halo2_gadgets`, `halo2_proofs`, `pasta_curves`, `sinsemilla`
  (MIT OR Apache-2.0), `jubjub`, `group`, `ff` (MIT/Apache-2.0), `blake2b_simd` (MIT);
- their dependencies, all under permissive licences.

`Image/` holds this binary's machine code decoded as Lean data.

## Layout

The image and memory:

| path | contents |
| --- | --- |
| `Image/`, `Image.lean` | `gen-image`'s output: one module per function (307; `INDEX.tsv` maps module to symbol), three data chunks, `Layout` and `Ro`. Cross-checked entry by entry against riscv-zkvm's `Interpreter.load`. `Image.lean` imports every function. |
| `Loaded.lean` | The layout is well formed; the entry stack word; `code_of_run` (every state an SP1 run reaches has the image's code); decode facts and `CodeOk` of the frame-checked functions. |
| `Regions.lean` | The address space, named and proved disjoint: stack, `.rodata`, `.eh_frame`, `.data`, `.bss`, the TLSF arena, the hint region. |
| `Statics.lean` | The protected statics (`.rodata`, `.eh_frame`, the two hooks nothing sets) and their load values. `Runtime/STATICS.tsv` is the reviewed list. |
| `Owned.lean` | The owning `Env`: the public-values hasher's tag and position, with the invariant `syscall_write` and `syscall_halt` keep. |
| `HeapEnv.lean` | The `Env` that also owns the allocator (control block and arena), with `HeapOk` (`Tlsf.Rep`) in the invariant. |

The checkers:

| path | contents |
| --- | --- |
| `Frame/` | The first frame-integrity checks (`MachineChecked.RiscV.Frame`) on `memcpy`, `PadAdapter::next`, `default_hook` and `core::fmt::write`. `Gen.lean` emits the annotations (`*Anno.lean`, untrusted certificates); each module has the kernel re-check them. |
| `Contract/` | The checked table, generated by `lake exe infer-contracts` (`Tools/Infer.lean`; the command is in `PLAN.md`'s E2 notes). `Table.lean` holds the `Env` and 70 interfaces: 68 inferred and certified by the contract checker (`A_<addr>.lean` the interface and certificate, `V_<addr>.lean` its proof), and two proved by hand and listed in `Runtime/GIVEN.tsv` (`memcpy`, `memset`). `All.lean` proves every interface holds for the loaded image (`Contract.all`). |

The runtime, proved with the symbolic executor (`MachineChecked.RiscV.Exec`):

| path | contents |
| --- | --- |
| `Runtime/Entry.lean` | From the loaded state to `main`'s entry; `MainEntry` fixes the stack, heap, statics and hasher. |
| `Runtime/SysWrite.lean`, `Halt.lean`, `ReadVec.lean` | `syscall_write` keeps the hasher's invariant; `syscall_halt` never accepts with a nonzero code; `read_vec_raw` with its bump region and `HINT_LEN`/`HINT_READ`. |
| `Runtime/Memcpy.lean`, `Memset.lean` | For every length, with footprints. |
| `Runtime/Tlsf/`, `Alloc/`, `Dealloc/`, `Realloc.lean` | rlsf's heap as memory holds it (`Tlsf.Model`, `Heap`, `Class`, `Update`, `Free`, and `Init` as the satisfiability witness), and `alloc`, `dealloc` and `__rust_realloc` against it. |
| `Runtime/Panic.lean`, `SysPanic.lean` | Panics never accept, from each entry down to `sys_panic` and `syscall_halt(1)`, given one premise: `panic_with_hook` never accepts (`pwhIface.Holds`). `Runtime/CFI.tsv` lists the control-flow premises of `core::fmt::write`'s formatter calls. |

The program and its statement:

| path | contents |
| --- | --- |
| `Field/`, `Curve/`, `Precompile/` | The Pallas fields in Montgomery form, curve arithmetic, and the SP1 precompiles (`UINT256_MUL`, `PALLAS_ADD`, `PALLAS_DOUBLE`) related to the mathematics. |
| `Blake2b/`, `Sha256/`, `Poseidon/`, `Sinsemilla/`, `Orchard/` | The hashes and the Orchard derivations the guest computes. |
| `Witness/` | The input parser (bincode/serde visitors). |
| `Main/` | `main`, in segments. |
| `Run/` | The run's heap invariant (`HeapAt`) and the allocator contracts at each call site, discharged. |
| `Bridge/` | Relates machine-level results to the specification; `Decode.lean` defines `GuestAccepts`. |
| `Top/` | The composition: `Accepting.lean` (`guest_accepting_run`, from `main`'s entry), `Assumptions.lean`, `Load.lean`, `Elf.lean` (`guest_elf_run`), `Loaded.lean` (`guest_loaded_run`), `Guest.lean` (`guest_run`). |
| `Kit/` | Shared lemmas (bytes, regions, Mathlib imports). |
| `Spec/` | The specification: `Spec/Zip2005` transcribes ZIP 2005, over vendored libraries under their upstream licences (`Zcash`, `Clean`, `CompElliptic`, `CompPoly`). Only this directory uses Mathlib. `Spec/Zip2005.lean` checks the axioms of its definitions. |
